# 15. 3Sum

**Medium** · [LeetCode](https://leetcode.com/problems/3sum/) · [Solution file (no hints)](../../problems/0001-0499/15.py)

[📖 02. Two Pointers lesson](../learning/02-two-pointers.md) · [🗺 Roadmap](../../roadmap.md) · [🧩 All 02. Two Pointers problems](../rmap-practice/02-two-pointers.md)

---

Given an integer array `nums`, return **all the unique triplets** `[nums[i], nums[j], nums[k]]` such that `i`, `j`, `k` are distinct indices and `nums[i] + nums[j] + nums[k] == 0`.

The solution set must not contain duplicate triplets.

```
nums = [-1,0,1,2,-1,-4]  →  [[-1,-1,2], [-1,0,1]]
nums = [0,1,1]           →  []
nums = [0,0,0]           →  [[0,0,0]]
```

**Constraints:** `3 <= nums.length <= 3000` · `-10⁵ <= nums[i] <= 10⁵`

<details>
<summary><b>1 · Scan the problem</b> — what the words are telling you</summary>

| The statement says | Which really means |
|---|---|
| "**three** numbers summing to 0" | Fix one, and the remaining question is *"find two that sum to `-x`"* — which is [Two Sum II](167-two-sum-ii-input-array-is-sorted.md). **Reduce, don't reinvent** |
| "return **all** triplets" | Not one answer — collect them. No early return |
| "must not contain **duplicate triplets**" | ⚠️ The real difficulty. Not duplicate *numbers* — duplicate **triplets**. `[-1,0,1]` twice is illegal, but `[-1,-1,2]` is fine |
| "the **values**, not the indices" | Unlike [Two Sum](1-two-sum.md), positions don't matter — so you're **free to sort** |
| n ≤ 3000 | n² = 9·10⁶ → fine. n³ = 2.7·10¹⁰ → dead. The target is **O(n²)** |
| `[0,0,0]` → `[[0,0,0]]` | Repeated values may legitimately appear *within* one triplet |

Two observations do all the work:

1. **Sorting is free here** because you return values, not indices. And sorting unlocks the two-pointer scan from [Two Sum II](167-two-sum-ii-input-array-is-sorted.md).
2. Once sorted, **duplicates sit next to each other** — which turns the hard deduplication requirement into a simple "skip if it equals the previous one" check.

So sorting solves *both* problems at once. That's the insight.

🤔 **Before you open the next section:** if you fix `nums[i]` and two-pointer the rest, when would you produce the *same triplet twice* — and how does sorted order let you detect that in O(1)?

</details>

<details>
<summary><b>2 · Choose the tool</b> — the options, and why one wins</summary>

| Approach | How it works | Time | Dedup | Verdict |
|---|---|---|---|---|
| Brute force | Three nested loops | O(n³) | Needs a set of sorted tuples | ❌ 2.7·10¹⁰ ops |
| Hash map inner | Fix one, hash-map two-sum the rest | O(n²) | Fiddly and error-prone | ⚠️ Right complexity, worse dedup story |
| Brute force + set | O(n³), dedupe via `set` of tuples | O(n³) | Easy | ❌ Still too slow |
| **Sort + fix one + two pointers** | Sort, loop `i`, converge on the remainder | **O(n²)** | **Free**, by skipping equal neighbours | ✅ |

**The decision: sort, then for each `i` run the [Two Sum II](167-two-sum-ii-input-array-is-sorted.md) two-pointer scan on the subarray to its right.**

For a fixed `nums[i]`, you need two elements summing to `-nums[i]`. The array is sorted, so that's exactly the converging-pointer routine — O(n) per fixed element, O(n²) overall.

**Why sorting is the linchpin.** It pays for itself three times over:
1. It enables the O(n) two-pointer inner scan.
2. It makes duplicates adjacent, so dedup becomes a neighbour comparison rather than a set of tuples.
3. It costs only O(n log n) — dominated by the O(n²) main loop, so it's effectively free.

**Why search only to the right of `i`?** Starting `left` at `i + 1` means every triplet is found in **sorted order** with strictly increasing indices, so you never produce `[a,b,c]` and later `[b,a,c]` as separate answers. Ordering is doing dedup work for you before you've written a single dedup line.

**Why not the hash-map inner loop?** Same O(n²), but deduplication with hashing is genuinely awkward — you end up canonicalizing triplets into sorted tuples and storing them in a set, which is extra memory and extra code to achieve what sorted order gives away.

</details>

**Dedup rule #1 — the first element.** If this value equals the previous one, we already ran the complete two-pointer scan for it and collected every triplet it can start. Running it again would reproduce the identical triplets.

The `i > 0` guard prevents `nums[-1]` from wrapping around to the last element. And note it compares to the **previous** value, not the next — we skip *repeats*, never the first occurrence.
→ [break-continue](../syntax/break-continue.md) · [logical-operators](../syntax/logical-operators.md)

```python

```

The two-pointer window over everything **after** `i`. Starting at `i + 1` guarantees three distinct indices and keeps each triplet in sorted order.
→ [variables-assignment](../syntax/variables-assignment.md)

```python

            left += 1
        elif nums[i] + nums[left] + nums[right] > 0:
```

The [Two Sum II](167-two-sum-ii-input-array-is-sorted.md) routine verbatim, with a three-way sum against 0. Too small → need bigger → `left` moves right. Too big → `right` moves left. Same correctness argument: each move discards an element that can't work with its best available partner.
→ [while-loop](../syntax/while-loop.md) · [elif-else](../syntax/elif-else.md) · [comparison-operators](../syntax/comparison-operators.md)

```python

            result.append([nums[i], nums[left], nums[right]])
            left += 1
            right -= 1
```

A hit. Record it, then move **both** pointers — with `nums[i]` fixed, the current `nums[left]` has found its only possible partner, so neither pointer can stay put.
→ [list-methods](../syntax/list-methods.md)

```python
            while left < right and nums[left] == nums[left - 1]:
                left += 1
```

**Dedup rule #2 — the second element.** After a hit, skip any repeats of the value just used. Without this, `[-2,0,0,2,2]` would report `[-2,0,2]` **twice** — once for each `(0,2)` pairing.

Only `left` needs the skip: `right` is forced to move in lockstep by the sum condition, so its duplicates are consumed automatically.
→ [while-loop](../syntax/while-loop.md)

```python
return result
```

Out of both loops — every starting element has been tried.

<details>
<summary>The whole thing together</summary>

```python
class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:

        nums.sort()
        result = []

        for i in range(len(nums)):

            if i > 0 and nums[i] == nums[i - 1]:
                continue

            left = i + 1
            right = len(nums) - 1

            while left < right:
                if nums[i] + nums[left] + nums[right] < 0:
                    left += 1
                elif nums[i] + nums[left] + nums[right] > 0:
                    right -= 1
                else:
                    result.append([nums[i], nums[left], nums[right]])
                    left += 1
                    right -= 1

                    while left < right and nums[left] == nums[left - 1]:
                        left += 1

        return result
```

</details>

**Trace it** — `nums = [-1,0,1,2,-1,-4]`, sorted to `[-4,-1,-1,0,1,2]`:

| `i` | `nums[i]` | Skip? | Inner scan | Found |
|---|---|---|---|---|
| 0 | −4 | no | needs +4 from `[-1,-1,0,1,2]`; max is 1+2=3 → nothing | |
| 1 | −1 | no | `(-1,2)` sums 0 ✅ → `[-1,-1,2]`; then `(0,1)` sums 0 ✅ → `[-1,0,1]` | 2 triplets |
| 2 | −1 | **yes** — equals `nums[1]` | skipped entirely | |
| 3 | 0 | no | `[1,2]` — smallest pair is 1+2=3 > 0 → nothing | |

Result: `[[-1,-1,2], [-1,0,1]]` ✅

Notice index 2 — without dedup rule #1, it would rediscover both triplets and return each twice.

</details>

<details>
<summary><b>4 · Time complexity</b> — O(n²)</summary>

**O(n²).**

| Step | Cost |
|---|---|
| Sort | O(n log n) |
| Outer loop | n iterations |
| Inner two-pointer scan | O(n) per iteration — pointers only converge, never reset |
| Dedup skips | Absorbed into the pointer movement, no extra cost |

n × O(n) = **O(n²)**, and O(n log n) + O(n²) = **O(n²)** since the quadratic term dominates.

**Why the inner scan is O(n) and not more:** within one `i`, `left` only increases and `right` only decreases until they meet. The inner duplicate-skipping `while` moves `left` forward too — it never resets, so it's part of the same linear budget. Same amortized reasoning as [Valid Palindrome](125-valid-palindrome.md).

At n = 3000 that's ~9·10⁶ operations — comfortably fast, and exactly why the constraint is 3000 rather than 10⁵.

**Is O(n²) optimal?** For 3Sum, essentially yes. It's a well-known result that 3Sum has no *substantially* sub-quadratic algorithm, and a whole class of problems ("3SUM-hard") is defined by reduction to it. You will not find an O(n log n) here — worth knowing so you don't burn interview time hunting.

</details>

<details>
<summary><b>5 · Space complexity</b> — O(1) auxiliary</summary>

**O(1) extra**, not counting the output — plus whatever the sort uses.

- `result` is the required output. In the worst case it holds O(n²) triplets, but output space is conventionally excluded.
- The pointers `i`, `left`, `right` are O(1).
- **The sort** is the honest caveat: Python's Timsort is O(n) space in the worst case. Some languages' in-place quicksort is O(log n) for the recursion stack.

**The precise answer:** *"O(1) auxiliary beyond the output, plus O(n) for Python's sort — or O(log n) with an in-place sort."* Saying just "O(1)" invites the challenge about sorting; naming it shows you know where every byte goes.

**Note the contrast with the hash-map approach:** it would need O(n) for the map *and* a set of seen triplets for dedup. Sorting buys you deduplication with **no data structure at all** — just neighbour comparisons. That's the recurring lesson of this unit: **structure in the input replaces auxiliary memory.**

</details>

<summary><b>6 · Talk it through</b> — trade-offs & follow-ups</summary>

**Say this out loud:**

> "Brute force is O(n³) and won't fit. The reduction is that if I fix one element, finding the other two is just Two Sum on the rest — and since I'm returning values rather than indices, I'm free to sort. Sorting gives me the two-pointer scan, which makes the inner search O(n) instead of O(n²), so overall O(n²). Sorting also solves the harder requirement: duplicates end up adjacent, so I dedupe by skipping a first element equal to its predecessor, and after each hit skipping repeats of the second element. O(n²) time, O(1) auxiliary space beyond the output."

**Follow-ups you should expect:**

| If they ask… | Answer |
|---|---|
| "Walk me through the deduplication." | **The question they're really asking.** Two rules: skip `nums[i] == nums[i-1]` at the outer level; after recording a triplet, advance `left` past equal values. Sorted order makes both O(1) checks. |
| "4Sum?" | Same idea nested one deeper: sort, two nested fixed loops, two-pointer the innermost. O(n³). |
| "k-Sum in general?" | Recurse: kSum fixes an element and calls (k−1)Sum, bottoming out at the two-pointer 2Sum. O(n^(k−1)). |
| "Closest sum to a target instead of exactly 0?" | Same scan, but track the minimum `abs(sum - target)` instead of returning on equality — and you can't skip on equality any more. |
| "Can you beat O(n²)?" | No meaningfully — 3Sum is conjectured to have no substantially sub-quadratic solution, and 3SUM-hardness is a standard reduction target. |
| "Add an early exit." | Once `nums[i] > 0` you can `break`: the array is sorted, so all three elements would be positive and can't sum to zero. |
| "What if you couldn't sort?" | Hash-map inner loop at O(n²) time, O(n) space — and you'd dedupe with a set of sorted tuples. Strictly more work. |

**Traps:**

- **Comparing `nums[i] == nums[i+1]`** instead of `nums[i-1]`. That skips the *first* occurrence and misses valid triplets — the mirror-image bug, and it's subtle.
- **Forgetting the `i > 0` guard** — `nums[-1]` wraps to the last element and silently skips index 0.
- **Omitting the inner dedup skip.** `[-2,0,0,2,2]` then returns `[-2,0,2]` twice.
- **Moving only one pointer after a hit.** With `nums[i]` fixed, the same `left` can't pair with anything else.
- **Deduping with a set of tuples** *and* sorting. It works, but it's admitting you didn't see what sorting already gave you.
- **`left = 0` instead of `i + 1`** — reuses elements and produces permutations of the same triplet.

# 18. 4Sum

**Medium** · [LeetCode](https://leetcode.com/problems/4sum/) · [Solution file (no hints)](../../problems/0001-0499/18.py)

[📖 02. Two Pointers lesson](../learning/02-two-pointers.md) · [🗺 Roadmap](../../roadmap.md) · [🧩 All 02. Two Pointers problems](../rmap-practice/02-two-pointers.md)

Given an array `nums` of `n` integers, return **all unique quadruplets** `[nums[a], nums[b], nums[c], nums[d]]` such that `a`, `b`, `c`, `d` are distinct indices and the four values sum to `target`. The answer may be returned in any order.

```
nums = [1,0,-1,0,-2,2], target = 0  →  [[-2,-1,1,2],[-2,0,0,2],[-1,0,0,1]]
nums = [2,2,2,2,2],     target = 8  →  [[2,2,2,2]]
```

**Constraints:** `1 <= n <= 200` · `-10⁹ <= nums[i] <= 10⁹` · `-10⁹ <= target <= 10⁹`

<details>
<summary><b>1 · Scan the problem</b> — what the words are telling you</summary>

| The statement says | Which really means |
|---|---|
| "**unique** quadruplets" | ⚠️ **The hard part.** Duplicate *values* are allowed in the input, but the output must contain no repeated quadruplet |
| "**distinct indices**" | You can't reuse the same position — but two equal *values* at different positions are fine (`[2,2,2,2]`) |
| "any order" | No sorting requirement on the output, which frees you to sort the input |
| `n` up to 200 | O(n⁴) = 1.6·10⁹ is too slow; **O(n³)** = 8·10⁶ is comfortable |
| values up to ±10⁹ | Four of them could sum to ±4·10⁹ — **overflow territory in C++/Java**, though not in Python |
| `target` arbitrary | Unlike [3Sum](15-3sum.md)'s fixed 0, so no sign-based shortcuts |

This is [3Sum](15-3sum.md) with **one more nesting level**, and recognizing the family is most of the work:

| Problem | Structure | Time |
|---|---|---|
| [Two Sum II](167-two-sum-ii-input-array-is-sorted.md) | two pointers | O(n) |
| [3Sum](15-3sum.md) | fix 1, two-pointer | O(n²) |
| **4Sum** | **fix 2, two-pointer** | **O(n³)** |
| k-Sum | fix k−2, two-pointer | O(n^(k−1)) |

The general recipe: **sort, fix the outer elements with nested loops, then converge two pointers on the innermost pair.**

The genuinely tricky part is uniqueness. With duplicates in the input, the same quadruplet can be reachable many ways. Sorting makes duplicates **adjacent**, which is what lets you skip them with a simple neighbour comparison — and that's the whole reason sorting is worth it beyond enabling the two pointers.

You need duplicate handling at **all four** levels: both fixed indices and both pointers.

🤔 **Before you open the next section:** if the array is sorted and you've just used a value at index `i`, how do you tell whether the next index would produce a quadruplet you've already emitted?

</details>

<details>
<summary><b>2 · Choose the tool</b> — the options, and why one wins</summary>

| Approach | How it works | Time | Space | Verdict |
|---|---|---|---|---|
| Brute force + set | All four-index combos, dedupe via a set of sorted tuples | O(n⁴) | O(n⁴) worst | ❌ 1.6·10⁹ ops |
| Fix 2, hash the rest | For each pair, hash-lookup complements | O(n³) | O(n) | ⚠️ Works, but deduping is painful |
| **Sort + fix 2 + two pointers** | Nested loops, converging pointers, skip duplicates | **O(n³)** | O(1)\* | ✅ |
| Recursive k-Sum | General k-sum, recursing down to 2-sum | O(n³) | O(k) | ✅ Elegant, generalizes |

**The decision: sort, two nested loops, then two pointers.**

Sorting does **two** separate jobs here, and it's worth naming both:

1. **Enables the two-pointer convergence** — a sorted array tells you which direction moves the sum.
2. **Makes duplicates adjacent** — so `nums[i] == nums[i-1]` is a complete test for "already handled this value," with no set needed.

**The duplicate-skipping rules, and why each looks the way it does:**

```python
if i > 0 and nums[i] == nums[i - 1]: continue          # first index
if j > i + 1 and nums[j] == nums[j - 1]: continue      # second index
```

Note the guards `i > 0` and `j > i + 1`. They mean *"skip only if this isn't the first value at this level."* You must **use** each distinct value once and skip only its repeats — skipping unconditionally would drop valid quadruplets like `[2,2,2,2]`.

For `j` the guard is `j > i + 1`, not `j > 0`: the first valid position for `j` is `i + 1`, and at that position there's no earlier `j` to compare against.

After recording a match, you also skip duplicates at both pointers:

```python
while left < right and nums[left] == nums[left + 1]: left += 1
while left < right and nums[right] == nums[right - 1]: right -= 1
left += 1
right -= 1
```

These advance *past* the run of equal values, then take one more step to move to genuinely new values. Both `left += 1` and `right -= 1` are needed — moving only one would re-find the same sum.

**Why not a hash-based approach?** Fixing two elements and hashing pairs gets O(n³) too, but you'd need to dedupe quadruplets explicitly with a set of sorted tuples — more memory and messier code. Sorting gives dedupe for free.

**The k-Sum generalization** is worth mentioning: write a recursive `kSum(nums, target, k)` that peels off one index per level and bottoms out at the two-pointer 2-sum. It's the answer to "now do 5Sum," and it shows you see the structure rather than the instance.

<summary><b>3 · Build the code</b> — block by block</summary>

```python
nums.sort()
result = []
n = len(nums)
```

Sort first — it enables both the pointer logic and the adjacency-based deduping.
→ [sorting-key](../syntax/sorting-key.md)

```python
for i in range(n - 3):
    if i > 0 and nums[i] == nums[i - 1]:
        continue
```

**First fixed element.** Stop at `n - 3` to leave room for three more elements.

The skip: if this value equals the previous one, every quadruplet starting here was already generated when we used the earlier copy. The `i > 0` guard ensures the *first* occurrence is always used.
→ [range-function](../syntax/range-function.md) · [break-continue](../syntax/break-continue.md)

```python
    for j in range(i + 1, n - 2):
        if j > i + 1 and nums[j] == nums[j - 1]:
            continue
```

**Second fixed element**, starting after `i` and stopping at `n - 2` to leave room for two.

Same skip logic, but guarded with `j > i + 1` — the first valid `j` has no predecessor within this `i`'s scope to compare against. Using `j > 0` here would incorrectly skip a valid `j == i + 1` whenever `nums[i] == nums[i+1]`.

```python
        left = j + 1
        right = n - 1
```

The converging pointers span everything after `j`.

```python
        while left < right:
            total = nums[i] + nums[j] + nums[left] + nums[right]
```

`left < right` strictly — the two pointers must never meet, which would use one index twice.
→ [while-loop](../syntax/while-loop.md)

```python
            if total == target:
                result.append([nums[i], nums[j], nums[left], nums[right]])
```

A hit. Record it — the values are already in ascending order thanks to the sort, so the quadruplet is in canonical form.
→ [list-methods](../syntax/list-methods.md)

```python
                while left < right and nums[left] == nums[left + 1]:
                    left += 1
                while left < right and nums[right] == nums[right - 1]:
                    right -= 1
                left += 1
                right -= 1
```

**Skip duplicate values at both pointers, then step past.**

The two `while` loops advance to the *last* element of each run of equal values; the final `+= 1` / `-= 1` then moves to a genuinely new value. Without this, `[2,2,2,2,2]` with target 8 would emit the same quadruplet many times.

The `left < right` guard inside each `while` prevents the pointers from crossing while skipping.

```python
            elif total < target:
                left += 1
            else:
                right -= 1
```

**The directional move.** Sum too small ⇒ take a larger left value. Too big ⇒ take a smaller right value. Standard converging two pointers.
→ [elif-else](../syntax/elif-else.md)

```python
return result
```

<details>
<summary>The whole thing together</summary>

```python
class Solution:
    def fourSum(self, nums: List[int], target: int) -> List[List[int]]:

        nums.sort()
        result = []
        n = len(nums)

        for i in range(n - 3):
            if i > 0 and nums[i] == nums[i - 1]:
                continue

            for j in range(i + 1, n - 2):
                if j > i + 1 and nums[j] == nums[j - 1]:
                    continue

                left = j + 1
                right = n - 1

                while left < right:
                    total = nums[i] + nums[j] + nums[left] + nums[right]

                    if total == target:
                        result.append([nums[i], nums[j], nums[left], nums[right]])

                        while left < right and nums[left] == nums[left + 1]:
                            left += 1
                        while left < right and nums[right] == nums[right - 1]:
                            right -= 1

                        left += 1
                        right -= 1

                    elif total < target:
                        left += 1
                    else:
                        right -= 1

        return result
```

</details>

**Trace it** — `nums = [1,0,-1,0,-2,2]` → sorted `[-2,-1,0,0,1,2]`, `target = 0`:

| `i` | `nums[i]` | `j` | `nums[j]` | `left` | `right` | `total` | Action |
|---|---|---|---|---|---|---|---|
| 0 | −2 | 1 | −1 | 2 | 5 | `-2-1+0+2 = -1` | `< 0` → `left=3` |
| 0 | −2 | 1 | −1 | 3 | 5 | `-2-1+0+2 = -1` | `< 0` → `left=4` |
| 0 | −2 | 1 | −1 | 4 | 5 | `-2-1+1+2 = 0` | ✅ **`[-2,-1,1,2]`**, pointers cross |
| 0 | −2 | 2 | 0 | 3 | 5 | `-2+0+0+2 = 0` | ✅ **`[-2,0,0,2]`**, pointers cross |
| 0 | −2 | 3 | 0 | — | — | — | **skipped** (`nums[3]==nums[2]`) |
| 1 | −1 | 2 | 0 | 3 | 5 | `-1+0+0+2 = 1` | `> 0` → `right=4` |
| 1 | −1 | 2 | 0 | 3 | 4 | `-1+0+0+1 = 0` | ✅ **`[-1,0,0,1]`**, pointers cross |
| 1 | −1 | 3 | 0 | — | — | — | **skipped** (duplicate `j`) |
| 2 | 0 | 3 | 0 | 4 | 5 | `0+0+1+2 = 3` | `> 0` → `right=4`, then `left==right` → end |

Result `[[-2,-1,1,2], [-2,0,0,2], [-1,0,0,1]]` ✅

Rows 5 and 8 show the `j`-level skip doing real work — without it, `[-2,0,0,2]` and `[-1,0,0,1]` would each be emitted twice.

<details>
<summary><b>4 · Time complexity</b> — O(n³)</summary>

**O(n³).**

- Sorting: O(n log n) — dominated.
- Outer loop `i`: O(n)
- Inner loop `j`: O(n)
- Two-pointer scan: **O(n)** — each iteration moves one pointer inward, so it's linear, not quadratic

Total: O(n) × O(n) × O(n) = **O(n³)**.

At n = 200 that's 8·10⁶ — fast. Brute force O(n⁴) would be 1.6·10⁹, roughly 200× worse.

**The pattern generalizes cleanly:** k-Sum via this method is **O(n^(k−1))**, because you fix k−2 elements with nested loops and finish with an O(n) two-pointer pass. That's the sentence to have ready if asked about 5Sum.

**Duplicate skipping doesn't change the bound** — it only reduces constants — but it is essential for *correctness*, not performance. Worth being explicit about that distinction.

</details>

<details>
<summary><b>5 · Space complexity</b> — O(1) auxiliary</summary>

**O(1) auxiliary**, excluding the output.

A handful of integers. The sort is in place (with the usual Timsort O(n) caveat), and no hash structures are used.

**The output itself** can be large — up to O(n³) quadruplets in pathological cases — but that's required by the problem, not overhead you chose.

**Compare to the hash-based alternative:** O(n) or more for the map, *plus* a set of seen quadruplets for deduping, which can reach O(n³). Sorting-based deduping avoids that entirely — another reason the sort earns its place.

This is the same lesson as [3Sum](15-3sum.md):

> **Sorting buys you two things at once: directional pointer movement, and free duplicate detection via adjacency.** Either alone might justify it; together they make it clearly correct.

</details>

<details>
<summary><b>6 · Talk it through</b> — trade-offs & follow-ups</summary>

**Say this out loud:**

> "This is 3Sum with one more level. I sort first, then fix two elements with nested loops and converge two pointers on the rest — O(n³) after an O(n log n) sort. Sorting does double duty: it lets me move pointers directionally based on whether the sum is under or over target, and it puts duplicates adjacent so I can skip them by comparing to the previous element. I need skips at all four levels — both fixed indices, guarded so the first occurrence of each value is still used, and both pointers after recording a match. O(1) extra space beyond the output. It generalizes: k-Sum is O(n^(k−1)) by fixing k−2 elements and finishing with two pointers."

**Follow-ups you should expect:**

| If they ask… | Answer |
|---|---|
| "Generalize to **k-Sum**." | Recursive `kSum(nums, target, k)`: peel one index per level, bottom out at the two-pointer 2-sum. O(n^(k−1)). |
| "Why `j > i + 1` and not `j > 0`?" | The first valid `j` is `i + 1`; there's no earlier `j` in this scope to compare with. `j > 0` would wrongly skip valid quadruplets. |
| "Why skip at both pointers after a match?" | Otherwise runs of equal values re-produce the same quadruplet. `[2,2,2,2,2]` with target 8 exposes it. |
| "Can you prune more aggressively?" | Yes — if `nums[i]*4 > target` break; if `nums[i] + 3*nums[n-1] < target` continue. Big practical speedups, same O(n³). |
| "Overflow?" | Not in Python. In C++/Java, four values at 10⁹ each sum to 4·10⁹, overflowing `int32` — use 64-bit. |
| "Dedupe with a set instead?" | Works — store sorted tuples — but costs O(number of results) memory and is slower. Sorting-based skipping is cleaner. |
| "Can you beat O(n³)?" | Not meaningfully. 3SUM is conjectured Ω(n²), and 4Sum inherits Ω(n³) by reduction under the same assumptions. |

**Traps:**

- **Skipping duplicates unconditionally.** Dropping the `i > 0` / `j > i + 1` guards discards the *first* occurrence of each value, losing valid answers like `[2,2,2,2]`.
- **Using `j > 0` for the second level.** Wrongly skips when `nums[i] == nums[i+1]`.
- **Only skipping at one pointer after a match.** Duplicate quadruplets slip through.
- **Forgetting `left += 1; right -= 1` after the skip loops.** The `while`s stop *on* the last duplicate; without the extra step you re-examine it and loop forever.
- **Loop bounds.** `i` to `n-3` and `j` to `n-2` — leaving room for the remaining elements. Off-by-one here causes `IndexError` or missed answers.
- **Forgetting to sort.** Breaks both the pointer logic and the dedupe strategy simultaneously.
- **`while left <= right`.** Lets a single index be used twice.
